# Spec: Deterministic Checklist & Hybrid Suggestions (smelt lint)

Date: 2026-10-08
Status: revised after audit (v2)

## Background

`evaluate_skill()` produces feedback from three layers: deterministic lint
checks, an LLM writing review, and LLM-generated improvement suggestions.
Today the suggestion layer is fully model-generated: `_judge_suggestions`
feeds behavior failures + lint issues + weak writing dimensions to a judge
and returns free-text suggestions. Two consequences:

1. Without a judge LLM, suggestions are skipped entirely — even though the
   lint layer already knows exactly what is wrong and how to fix it.
2. The LLM spends tokens paraphrasing deterministic findings, and its output
   is non-reproducible run-to-run for issues that are fully deterministic.

Direction: **lint is the skeleton; the model keeps only semantic judgment.**
Suggestions become a checklist generated by code first, with the LLM
commenting only on what code cannot decide.

Normative basis for the new checks: Anthropic, "Skill authoring best
practices" (platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices),
specifically the YAML frontmatter rules, the 500-line body budget,
progressive-disclosure rules (references one level deep), the no-backslash
path rule, and the closing "Checklist for effective Skills".

## Goal

Turn smelt's feedback into a code-first checklist:

1. Every lint message carries a concrete fix hint.
2. Suggestions are generated from lint evidence by code; the LLM only adds
   suggestions for writing/behavior evidence; no-judge runs still produce a
   useful checklist.
3. New static checks cover the mechanically-checkable items of Anthropic's
   skill checklist, so the writing review can drop those dimensions.

## Non-goals (out of scope)

- Bilingual (zh/en) consistency checking — downstream-specific, needs config
  for language pairing; revisit when a concrete consumer asks.
- Semantic checks (description accuracy, example correctness) — remain LLM.
- Same-file anchor links (`[text](#section)`) — only links to *other* local
  files with `#anchor` fragments are validated.
- Changing score weights, grade thresholds, or `then/judge.py`.

## Requirements

### R1. `Message` gains an optional fix hint

`smelt/lint/models.py`: `Message` gets `fix: str | None = None` (third field,
default None — existing positional construction `Message(Severity.X, "...")`
must keep working).

### R2. All existing checks annotate fixes

Every `Message` emitted by the six current checks (metadata, structure,
trigger, clarity, assets, testcoverage) gets a short, imperative `fix` text
(e.g. assets missing file → "create the file or remove the reference").
Fix text is static per message kind; no LLM involved. Fix texts must not
contain `|` characters (they render inside a Markdown table cell).

### R3. Renderers surface fixes (lint report + evaluation JSON)

- `render_text`: append ` → {fix}` after the message text when present.
- `render_markdown`: same suffix inside the Issues cell.
- `render_json`: message objects include `"fix"` only when not None.
- `SkillEvaluation.to_dict()` (evaluate.py:182) applies the same rule to its
  lint-message serialization, so both JSON surfaces carry the same schema.

### R4. Code-generated suggestions

`smelt/evaluate.py`:

- New `_code_suggestions(lint_report, max_items) -> list[str]`: flattens all
  lint messages that carry a fix, ordered by severity (ERROR first), ties
  keep check order; each formatted as `"[{check_id}] {message} → {fix}"`;
  capped at `max_items`.
- `SkillEvaluationBuilder.run()`:
  - judge is None → `evaluation.suggestions = _code_suggestions(...)` and
    `suggestions_error = None` when lint ran; if lint is disabled, keep the
    current skip message.
  - judge present → code suggestions first; the judge is only called when
    `len(code_suggestions) < suggestions_max` AND evidence is non-empty
    (below); LLM suggestions are appended, deduplicated by exact string
    after `.strip()`, total capped at `suggestions_max`.
- `_build_evidence` drops the `lint_issues` block (code owns lint findings
  now); it keeps `behavior_tests` and `weak_writing_dimensions`. When both
  are empty, `_judge_suggestions` is not called.
  - Consequence for an existing test: `test_writing_unparseable_judge_output`
    (tests/test_evaluate.py:145-151) currently asserts truthy suggestions
    with a garbage-first judge on good-skill. Under the new rule the judge
    is never called for suggestions there; the test must be updated to
    assert `suggestions == []` and `suggestions_error is None` (writing
    fault-tolerance assertions stay).
- Empty state: when suggestions are enabled, lint ran, and nothing was
  found, `to_markdown` must not print "(not enabled)"; print
  "No lint issues; nothing to suggest." instead (evaluate.py:280-285).

### R5. New static checks (Anthropic-checklist coverage)

Folded into existing checks — no new check_ids, no weight changes. All new
findings are WARNING severity with -10 each, except R5.1 name-format
violations which are ERROR with -10 each. Note: an ERROR with -10 leaves a
check's score ≥ 60, so the check still passes by the score threshold — this
is intended; severity signals urgency, not gating.

1. **metadata** (extend):
   - `name` not matching `^[a-z0-9-]+$`, longer than 64 chars, or containing
     "anthropic"/"claude" (case-insensitive substring) → ERROR each. (The
     Anthropic XML-tag rule is subsumed by the charset rule and is not
     checked separately.)
   - `description` starting with first/second person (case-insensitive
     prefixes `I `, `I'`, `We `, `You `) → WARNING (spec requires third
     person).
   - Existing name==dir, description presence and 30–500 length rules stay.
     (500 is smelt's stricter style budget; the platform hard limit is
     1,024 — no new rule needed for that.)
2. **structure** (extend):
   - Heading level skip (H2 directly to H4, etc.) → WARNING.
   - More than one H1 → WARNING.
   - Headings must come from a new token-based helper (see R8), NOT from
     `skill.sections` — the loader's regex matches `#` lines inside code
     fences and would produce phantom headings.
   - Existing H2-count and word-count rules stay (still on `skill.sections`
     to avoid behavior change; only the new rules use token headings).
3. **clarity** (extend):
   - Body over 500 lines → WARNING. Count: `len(skill.body.splitlines())`
     (frontmatter already excluded by the loader).
   - Fenced code block with an empty info string whose content looks like
     code → WARNING, one message per block capped at 3. Needs a new
     `fences()` helper (R8). "Looks like code": ≥2 lines matching
     `^\s*(def |class |import \S|from \S|function |const |let |var |#!
     |<template>|<script>|public |private )`. Residual false-positive class
     (prose lines starting with these words) is accepted and documented in
     the check's docstring; plain-text fences (directory trees, console
     output) do not match these patterns.
   - Existing placeholder/word-count rules stay.
4. **assets** (extend):
   - Backslash in a link/image target or in an inline code span that starts
     with a known dir prefix (scripts/templates/assets/references/examples/
     docs/tests) → WARNING "use forward slashes". Needs a new
     `inline_code()` helper (R8): existing regexes only see forward-slash
     paths, so this scans `link_targets()` output and `code_inline` token
     contents directly.
   - Local markdown link `file.md#anchor`: target file exists but anchor
     matches no heading slug in it → WARNING. Slugging follows GitHub
     semantics: lowercase; strip punctuation (anything that is not a word
     char, space, or hyphen); spaces → hyphens; CJK kept (word chars under
     UNICODE); duplicate headings get `-1`, `-2` suffixes in document order;
     URL-decode the fragment before matching; closing-sequence hashes
     (`## Title ##`) are handled because headings come from tokens, not
     regex. Headings of the target file come from the R8 helper.
   - Reference depth: a local `.md` file linked from SKILL.md that itself
     contains local links → WARNING ("references should be one level deep;
     Claude may partially read nested files"). "Local links" = entries from
     `link_targets()` not starting with `http://`, `https://`, `mailto:`,
     `#`; image targets excluded. Only one nesting level is checked; an
     unreadable target file is skipped silently.
   - Existing existence rules and scoring stay.

### R6. Writing-review dimension convergence

`DEFAULT_DIMENSIONS` shrinks from 5 to 3:

1. "Semantic accuracy (does the name/description capture what the skill
   actually does)"
2. "Examples & edge cases (examples are correct and cover failure paths)"
3. "Actionability (steps are explicit, executable, unambiguous)"

Rationale: trigger guidance and structure/readability are now covered by
static checks (trigger check, R5.2/R5.3), so those dimensions are dropped;
the old "Metadata & naming" dimension is *replaced* by the narrower
semantic-accuracy dimension (its mechanical parts moved to R5.1).
Custom dimensions passed via `.with_writing(dimensions=...)` are unaffected.

### R7. Rename good_skill → good-skill

The R5.1 charset rule is normative (Anthropic), and `examples/good_skill`
violates it. Rename the directory to `examples/good-skill`, set frontmatter
`name: good-skill`, and update every reference: tests/test_lint.py
(`test_load_good_skill`, `test_discover_skills_scans_children`, CLI output
assertions), tests/test_lint_extra.py, tests/test_evaluate.py
(`test_full_evaluation_pipeline` asserts `lint_score == 1.0`), README
examples. Discover by grepping the repo for `good_skill`.

### R8. New helpers in `smelt/lint/markdown.py`

- `headings(body) -> list[tuple[int, str]]` — from `heading_open` block
  tokens (level from tag, text from the following inline token); immune to
  `#` inside code fences.
- `fences(body) -> list[tuple[str, str]]` — `(info, content)` per fenced
  block (info string preserved, may be empty).
- `inline_code(body) -> list[str]` — contents of `code_inline` tokens.

Existing `link_targets`, `prose_segments`, `code_contents` stay unchanged.

- CLI no-judge notice (src/smelt/lint/cli.py or evaluate CLI, around
  cli.py:69 — "writing review and suggestions will be marked as skipped")
  must be reworded: suggestions are no longer skipped without a judge.
- README: update the evaluate section (code-first suggestions, new default
  dimensions, no-judge checklist).

## Acceptance criteria

- `pytest`: full suite green, including new tests for every requirement.
- `ruff check src tests`: clean.
- No judge, on `examples/bad_skill`:
  `evaluate_skill(bad_skill).with_suggestions().run()` yields suggestions
  equal to `_code_suggestions(lint_report, max)` with
  `suggestions_error is None`.
- No judge, on clean `examples/good-skill`: suggestions == [], no error, and
  the markdown report shows the "nothing to suggest" empty state.
- With `ScriptedLLM` judge: code suggestions come first, LLM suggestions
  follow, `_build_evidence` output has no `lint_issues` key; when code
  suggestions already reach `suggestions_max`, the judge is not called.
- `examples/good-skill` keeps grade A; `examples/bad_skill` still fails
  lint; no new check fires on good-skill.

## Design constraints

- TDD: every requirement gets a failing test before implementation.
- DRY: all new markdown extraction lives in `smelt/lint/markdown.py` (R8);
  checks consume helpers, they do not re-parse.
- Backward compatibility: `Message` positional args, JSON schemas (no new
  null fields), check_ids, weights, public API signatures unchanged.
